# 세션은 폴더에 묶인다 — /resume과 프로젝트 스코프

`/resume`을 눌렀을 때 뜨는 세션 목록이 **무엇을 기준으로 모인 것인지** 궁금해서 파봤다. 답은 "지금 `claude`를 실행한 폴더". Claude Code에서 **프로젝트라는 건 등록하는 무엇이 아니라 실행한 디렉터리 그 자체**였다. 덤으로 세션 기록 파일을 직접 열어보다 `/resume`이 새 파일을 만들지 않고 **원래 파일에 계속 이어붙인다**는 것도 확인했다.

## 1. `/resume` 목록의 기준 = 실행한 폴더

세션 기록은 홈 디렉터리 아래에, **경로를 인코딩한 폴더명**으로 나뉘어 저장된다. 경로의 `/`를 `-`로 바꾼 이름이다.

```
~/.claude/projects/
├── -Users-gracej                                   ← 홈에서 실행한 세션
├── -Users-gracej--claude                           ← ~/.claude 에서 실행
├── -Users-gracej-Claude-my-blog                    ← 이 블로그 (세션 8개)
├── -Users-gracej-Claude-Projects-study-claude-code
├── -Users-gracej-test-logs
└── -Volumes-Samsung-T5-.../vtt...
```

`/resume`은 이 중 **현재 폴더에 해당하는 디렉터리 안의 세션만** 보여준다. 다른 폴더 세션은 목록에 아예 안 뜬다.

| 상황 | 결과 |
| --- | --- |
| `cd ~/Claude/my-blog` 후 `/resume` | 블로그 세션만 |
| 홈에서 실행 후 `/resume` | 홈 세션만 (블로그 세션 안 보임) |
| 서브폴더(`my-blog/apps/`)에서 실행 | **별개 프로젝트** 취급 → 다른 목록 |
| 폴더 이름을 바꾸면 | 경로가 달라져 목록에서 사라짐 (파일은 남아있음) |

즉 "세션을 못 찾겠다" 싶으면 대부분 **다른 디렉터리에서 실행한 경우**다. `pwd`로 확인하면 된다.

## 2. 프로젝트 = 폴더, 다만 스코프는 계층적이다

프로젝트를 만드는 절차도, 프로젝트 파일도 없다. 그냥 `claude`를 실행한 위치가 곧 프로젝트다. 그 폴더에서 자동으로 읽히는 것들:

```
~/Claude/my-blog/          ← 여기서 실행 = 이게 "프로젝트"
├── CLAUDE.md              ← 프로젝트 지침 (자동 로드)
├── .claude/
│   ├── settings.local.json   ← 이 프로젝트 전용 권한·설정
│   ├── commands/             ← 이 프로젝트 전용 슬래시 명령
│   └── skills/               ← 이 프로젝트 전용 스킬
├── .git/
└── apps/, posts/, css/, ...
```

그런데 **모든 것이 폴더에 1:1로 묶이는 건 아니다.** 항목마다 기준이 다르다.

| 항목 | 기준 |
| --- | --- |
| 세션 기록(`/resume`) | **실행한 경로 문자열 그대로.** 서브폴더는 다른 프로젝트 |
| `CLAUDE.md` | 상위 폴더까지 **거슬러 올라가며** 전부 읽음 |
| `.claude/` 설정 | 프로젝트 것 + `~/.claude/` 전역 것이 **합쳐짐** |
| Git 저장소 | **무관.** git이 아니어도 프로젝트가 되고, git root가 기준도 아님 |

세션은 폴더에 딱 묶이지만, **지침·설정은 위로 상속되는 계층 구조**다. 그래서 전역으로 쓰고 싶은 스킬·명령은 `~/.claude/` 아래에 두면 모든 프로젝트에서 보인다.

예외가 하나 있다. `/add-dir <경로>`를 쓰면 한 세션이 여러 폴더를 다룰 수 있다. 이때만 "프로젝트 ⊃ 폴더"가 된다. 세션 기록은 여전히 처음 실행한 폴더에 저장된다.

## 3. 지금 이 대화의 정체

`/resume`을 취소했으니 아무것도 불러오지 않았다. 그러면 지금 대화는 무엇인가 — **터미널에서 `claude`를 실행한 순간 새로 태어난 세션**이다.

```
세션 ID  : 3e0f717a-51c1-4327-9fc0-9edf56de75c1
기록 파일 : ~/.claude/projects/-Users-gracej-Claude-my-blog/3e0f717a-....jsonl
생성 시각 : 20:58  (claude 실행한 순간)
```

`claude`를 실행하면 무조건 새 UUID가 발급되고 `.jsonl` 파일이 하나 생긴다. 주고받는 모든 메시지가 실시간으로 그 파일에 **한 줄씩 append**된다. 그래서 `/resume` 목록의 가장 최신 항목이 곧 지금 진행 중인 대화였다.

## 4. 기존 세션들과의 관계 — 형제일 뿐

기술적으로는 **아무 관계 없다.** 같은 폴더에 사는 독립된 파일들이다.

```
-Users-gracej-Claude-my-blog/
├── 7b110564...  07-11 17:38   4K
├── a2065b8f...  07-24 19:13  44K
├── 876a1f03...  07-24 21:09 104K
├── 620799f9...  07-26 16:58 136K
├── 9dee9f81...  07-26 18:23 2.6M
├── f2cb3b91...  07-26 20:40  14M   ← 07-11부터 계속 이어온 세션
├── 64b00cb6...  07-26 20:40   4K
└── 3e0f717a...  07-26 20:58  56K   ← 지금 이 대화
```

대화 내용은 서로 못 본다. 그런데 **공유되는 게 따로 있다.**

| 공유됨 (모든 세션 공통) | 공유 안 됨 |
| --- | --- |
| `CLAUDE.md` 프로젝트 지침 | 대화 히스토리 |
| `.claude/` 설정·권한·스킬·명령 | 컨텍스트 |
| `memory/MEMORY.md` (세션 간 기억) | 진행 중이던 작업 상태 |
| 파일시스템·git 저장소 | |

새 세션인데도 "지난번에 배운 컨텍스트 관리"를 이어서 설명할 수 있었던 건 대화를 봐서가 아니라 **메모리에 적혀 있었기 때문**이다. 세션 간 연결은 오직 이 경로로만 일어난다.

## 5. 실측 — `/resume`은 새 파일을 만들지 않는다

14MB짜리 `f2cb3b91` 파일 안의 타임스탬프 분포를 세어봤다.

```
 271건  07-11      365건  07-17      355건  07-22
  60건  07-12      446건  07-18      281건  07-23
                    53건  07-19      220건  07-24
                    59건  07-20      473건  07-26
```

**7월 11일에 시작해 26일까지, 보름간 같은 파일 하나에 계속 쌓였다.** 즉 `/resume`으로 이어붙일 때마다 새 세션이 생기는 게 아니라 **원래 세션 ID를 유지하며 같은 파일에 append**된다. 그동안 이 세션 하나를 계속 되살려 쓴 것이었다.

| 구분 | 새로 실행 (`claude`) | 이어받기 (`/resume`) |
| --- | --- | --- |
| 세션 ID | 새로 발급 | **기존 ID 유지** |
| 파일 | 새 `.jsonl` 생성 | **기존 파일에 추가** |
| 컨텍스트 | 빈 상태 (CLAUDE.md·메모리만) | 과거 대화 복원 |
| 파일 크기 | 0부터 | 계속 커짐 (→ 14MB) |

## 6. 토큰 관리와 이어지는 지점

앞서 정리한 `/clear`·`/compact`와 바로 연결된다. 세 명령이 하는 일이 층으로 나뉜다.

| 명령 | 하는 일 |
| --- | --- |
| `/compact` | 현재 세션 안에서 히스토리를 **요약해 압축** |
| `/clear` | 컨텍스트를 **비우고** 새 세션 시작 (기록은 디스크에 남음) |
| `/resume` | 디스크에 남은 **이 폴더의** 과거 세션을 되살림 |

그래서 `/clear`를 눌러도 진짜 사라지는 게 아니고, `/resume`으로 돌아올 수 있다. 단 같은 폴더에서 실행했을 때만. 반대로 오래 `/resume`으로 끌고 온 세션은 파일도 컨텍스트도 무거워지니, 주제가 바뀌면 `/clear` 하거나 아예 새 터미널로 새 세션을 여는 게 낫다.

## 실습하며 나온 질문들 (Q&A)

***Q). `/resume`에서 고를 수 있는 세션들은 지금 폴더 기반으로 만든 세션들 대상인 거야?***
A). 맞다. 세션 기록은 `~/.claude/projects/<경로를-인코딩한-폴더명>/` 아래에 `.jsonl`로 저장되고, `/resume`은 **현재 폴더에 해당하는 디렉터리 안의 세션만** 보여준다. 이 맥에는 홈·`~/.claude`·블로그·study 폴더 등 6개 프로젝트 디렉터리가 있는데, 블로그 폴더에서 실행하면 그 안의 8개만 목록에 뜬다. 서브폴더에서 실행하면 경로 문자열이 달라져 별개 프로젝트로 취급되니, 세션이 안 보이면 `pwd`를 먼저 확인하면 된다.

***Q). 그러면 프로젝트와 폴더는 같은 개념으로 보면 되나?***
A). 거의 같다. 정확히는 **"프로젝트 = `claude`를 실행한 그 폴더"** 다. 등록 절차도 프로젝트 파일도 없다. 다만 항목마다 기준이 달라서, 세션 기록은 실행 경로에 1:1로 묶이는 반면 `CLAUDE.md`는 상위 폴더까지 거슬러 올라가며 읽히고 `.claude/` 설정은 전역(`~/.claude/`) 것과 합쳐진다. git 저장소 여부와는 무관하다. 즉 **세션은 폴더 단위, 지침·설정은 상속되는 계층**이다. 예외로 `/add-dir`을 쓰면 한 세션이 여러 폴더를 다룰 수 있다.

***Q). 지금 이 터미널에서는 resume을 실행하지 않았어. 그러면 지금 대화 중인 세션은 정체가 뭐야?***
A). `claude`를 실행한 순간 **새로 발급된 세션**이다. 새 UUID(`3e0f717a-...`)와 `.jsonl` 파일이 생기고, 주고받는 모든 메시지가 실시간으로 그 파일에 한 줄씩 append된다. `/resume` 목록에서 봤던 8개 중 **가장 최신 항목이 바로 진행 중인 이 대화**였다.

***Q). 기존 세션들과의 관계는?***
A). 기술적으로는 관계 없다. 같은 폴더에 사는 형제 파일들이고 서로의 대화 내용은 못 본다. 대신 `CLAUDE.md`·`.claude/` 설정·스킬·명령·`memory/MEMORY.md`·파일시스템·git은 모든 세션이 공유한다. 새 세션이 이전 학습 맥락을 알고 있었던 건 대화를 봐서가 아니라 **메모리 파일에 적혀 있었기 때문**이다. 세션 간 연결은 오직 그 경로로만 일어난다.

***Q). `/resume`으로 이어받으면 새 세션 파일이 생기나?***
A). 아니다. **기존 세션 ID를 유지하며 원래 파일에 계속 append**된다. 14MB짜리 파일 하나의 타임스탬프를 세어보니 07-11부터 07-26까지 보름간의 기록이 한 파일에 들어 있었다. 반대로 `claude`를 새로 실행하면 새 ID·새 파일로 0부터 시작한다. 그래서 오래 resume해 온 세션은 파일도 컨텍스트도 계속 무거워진다.

## 마무리

`/resume` 목록이 어디서 오는지 하나를 파봤더니, 지금까지 만든 것들이 전부 같은 원리 위에 있다는 게 보였다. `CLAUDE.md`, `.claude/skills/`, `.claude/commands/`, `settings.local.json`, 세션 기록 — 다른 폴더로 가면 전부 안 보이는 이유는 하나다. **프로젝트 폴더가 곧 스코프.** 그리고 기록 파일을 직접 열어 타임스탬프를 세어보는 것만으로 `/resume`의 동작을 확인할 수 있었다는 점이 오늘의 수확이다. 문서를 찾기 전에 파일을 보면 되는 경우가 생각보다 많다.
