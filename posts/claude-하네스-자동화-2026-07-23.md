# Claude Code 하네스 익히기 — 컨텍스트 관리부터 슬래시 명령·스킬까지

오늘은 코드를 만들기보다 **Claude Code라는 도구 자체를 이해하고 내 손에 맞게 자동화**하는 데 집중했다. 컨텍스트가 어떻게 차고 비워지는지, 대화가 어디에 저장되고 어떻게 되살아나는지, 로컬과 클라우드가 어떻게 다른지 배웠다. 그리고 반복 작업을 **커스텀 슬래시 명령**과 **스킬**로 자동화하는 것까지 실습했다.

## 1. 컨텍스트 윈도우와 서브에이전트

- 컨텍스트는 글자가 아니라 **토큰** 단위로 센다. 지금 쓰는 모델의 창은 대략 **20만 토큰** 규모다.
- 이 창에는 대화 전체 + 도구 호출과 결과 + 시스템 지침이 들어간다.
- 핵심: **서브에이전트가 한 작업량은 이 창에 포함되지 않는다.** 서브에이전트는 자기만의 별도 창에서 돌고, 메인으로는 **최종 요약만** 돌아온다. 그래서 서브에이전트는 오히려 메인 컨텍스트를 아껴준다.

## 2. /compact 은 주기적으로 쓰지 말 것

`/compact`은 대화를 요약본으로 압축해 공간을 비운다. 하지만 **요약 = 손실**이라, 습관적으로 자주 쓰면 얻는 것 없이 디테일만 잃는다. 자동 압축이 이미 있어 대개 손댈 필요가 없다.

| 상황 | 권장 |
| --- | --- |
| 그냥 주기적으로 | ❌ 불필요, 순손실 |
| 작업 도중 | ❌ 손실 위험 |
| 큰 새 작업 시작 직전 | ✅ 깨끗한 창으로 |
| 완전히 다른 주제 | ✅ `/compact`보다 `/clear` |

## 3. 대화 저장 위치와 /resume

대화는 로컬 파일로 남는다.

| 위치 | 내용 |
| --- | --- |
| `~/.claude/projects/<프로젝트>/<세션id>.jsonl` | 대화 본체(전체 기록) |
| `.../subagents/agent-<id>.jsonl` | 서브에이전트별 로그 |
| `~/.claude/history.jsonl`, `file-history/`, `backups/` | 입력 히스토리·파일 편집 체크포인트 |

`/resume`은 이 `.jsonl` 기록을 되감아 대화 상태를 재구성하고 그 지점부터 이어가는 기능이다. `/compact`은 "활성 컨텍스트"만 바꿀 뿐 이 파일을 지우지 않으므로, **원본 디테일은 대개 디스크에 그대로 남아** 있어 나중에 찾아 복구할 수 있다.

## 4. 로컬 Code vs 클라우드(챗·코워크)

추론(응답 생성)을 위해 프롬프트가 API로 전송되는 건 공통이다. **차이는 "대화 기록을 어디에 보관하느냐"** 다.

| | 실행 위치 | 기록 보관 |
| --- | --- | --- |
| Claude Code (로컬) | 내 컴퓨터 | 로컬 디스크 |
| 챗·코워크·클라우드 에이전트 | 클라우드 | 클라우드(계정) |

Cowork는 그 중간(하이브리드)이다. 대화는 클라우드에 두고, 로컬 파일 접근은 내 기계의 브리지를 통한다. 그래서 **컴퓨터를 바꾸면 대화는 계정 따라 복원되지만 로컬 파일 연결은 다시 맺어야** 한다. 파일을 git이나 동기화 드라이브에 두면 이동이 쉽다.

## 5. 자동화 1 — 커스텀 슬래시 명령

매일 "오늘 배운 것 요약해서 올려줘"를 반복하는 대신 **커스텀 슬래시 명령**으로 만들었다.

- 위치: `.claude/commands/<이름>.md` (md 1개 = 프롬프트 템플릿)
- 발동: 내가 `/이름` 을 직접 입력
- 이 글도 그렇게 만든 `/study-upload` 명령의 결과물이다.
- **파일명 규칙**: 블로그 글은 `<제목>-<날짜>.md` 로 만든다. slug 허용 문자는 `영문/숫자/한글/하이픈/언더스코어`뿐이라 **공백·점 금지**, 날짜는 하이픈으로. `posts.json`의 slug는 파일명과 정확히 같아야 링크가 열린다.
- **주의**: 슬래시 명령·스킬은 **세션 시작 시 로드**되므로, 새로 만들면 세션을 재시작해야 목록에 뜬다.

## 6. 자동화 2 — 스킬(Skill)

슬래시 명령보다 큰 단위의 자동화는 **스킬**로 만든다.

| | 슬래시 명령 | 스킬 |
| --- | --- | --- |
| 형태 | md 파일 1개 | **폴더** (`SKILL.md` + 참고문서·스크립트) |
| 발동 | 내가 `/명령` 입력 | 내가 부르거나, **description에 맞으면 Claude가 자동 선택** |
| 규모 | 가벼운 매크로 | 여러 파일을 묶은 패키지 |

오늘 이 블로그의 하네스(작업 사이클·폴더 구조·서브에이전트 설정·웹앱 규칙)를 통째로 `webapp-blog-jek` 스킬로 패키징했다. `SKILL.md`의 **description**이 "언제 이 스킬을 쓰는가"를 정의하는 가장 중요한 부분이다.

- **스코프**: `<프로젝트>/.claude/skills/` = 그 프로젝트에서만, `~/.claude/skills/` = 모든 프로젝트(전역).
- `.claude/`는 `.gitignore` 대상이라 git엔 안 올라가고 로컬에만 남는다(개인 하네스라 적절).

## 실습하며 나온 질문들 (Q&A)

**Q). 한 컨텍스트 윈도우에 얼마나 담아? 서브에이전트가 쓴 용량도 포함돼?**
A). 대략 20만 토큰. 서브에이전트 작업량은 **포함되지 않는다** — 별도 창에서 돌고 최종 요약만 메인으로 돌아온다.

**Q). `/compact`을 주기적으로 쓰는 게 좋아, 아니면 손실만 생기는 짓이야?**
A). 주기적 사용은 비권장. 요약 압축이라 손실이 생기고 자동 압축이 이미 있다. 큰 새 작업 시작 등 목적이 있을 때만, 완전 새 주제면 `/clear`가 낫다.

**Q). 대화 jsonl을 백업했다 compact 후 손실 심하면 되돌리면 안 돼? 다른 데도 저장돼?**
A). 백업은 무해하지만, `/compact`이 그 파일을 지우지 않아 원본이 대개 남아 있어 복구 가능하다. 파일을 손으로 되돌려 compact를 "취소"하는 건 정식 방식이 아니며, 정식 방법은 `/resume`이다. 저장소는 대화 jsonl 외에 subagents 로그·history·file-history·backups 등 여러 곳이다.

**Q). `/resume`은 정확히 뭘 해?**
A). 저장된 세션 `.jsonl`을 읽어 기록된 메시지·도구 호출·결과를 순서대로 복원해 대화를 재조립하고 그 지점부터 이어 쓴다. 로컬 파일만 읽으므로 이 컴퓨터의 Code 세션만 대상이다.

**Q). 로컬 Code는 왜 클라우드로 자동 업로드 안 하고 챗·코워크는 올려?**
A). 제품이 실행되는 곳에 데이터가 남기 때문이다. Code는 로컬 도구라 기록도 로컬에 두는 게 자연스럽고, 소스코드·비밀값을 다뤄 프라이버시상 안전한 기본값이다. 챗·코워크는 클라우드 서비스라 클라우드에 보관·동기화된다.

**Q). Cowork도 컴퓨터 폴더 파일을 읽는데, 대화는 클라우드면 파일 연결은 어떻게? 기기를 바꾸면?**
A). 하이브리드다. 대화는 클라우드, 파일 접근은 로컬 브리지를 통하고 클라우드엔 파일이 아니라 워크스페이스 참조가 저장된다. 기기를 바꾸면 대화는 복원되지만 로컬 파일 연결은 다시 맺어야 한다.

**Q). 커스텀 슬래시 명령을 만드는 건 코워크에서 일정을 만드는 것과 내부 동작이 같아?**
A). 다르다. 슬래시 명령은 내가 입력해야 도는 **로컬 매크로**, 코워크 일정은 정해진 시각에 자동으로 도는 **클라우드 작업**이다. "로컬 대화 요약"은 재료가 로컬 대화라 슬래시 명령이 맞고, 클라우드 스케줄로는 그 대화에 접근할 수 없다.

**Q). `/skill-creator`가 안 돼. 앱에는 있는데?**
A). `skill-creator`는 "스킬"이지 "슬래시 명령"이 아니라서 `/`로는 안 불린다. 스킬은 상황에 맞춰 Claude가 Skill 도구로 불러온다. 앱 설정에 보이는 건 claude.ai 앱 쪽 스킬 목록으로, Code에서 `/`로 치는 것과는 별개다.

**Q). 스킬을 다른 세션에서도 쓰려면?**
A). 같은 프로젝트의 다른 세션에서는 프로젝트 스킬이 이미 로드되어 그대로 쓸 수 있다. 다른 프로젝트에서도 쓰려면 `~/.claude/skills/`(전역)로 복사한다. 단 경로가 프로젝트에 종속적이면 그 부분은 일반화가 필요하다.

## 마무리

오늘은 "도구를 쓰는" 단계에서 "도구가 어떻게 도는지 이해하고, 내 방식대로 자동화하는" 단계로 넘어갔다. 컨텍스트·저장 구조를 알고 나니 왜 그렇게 동작하는지 납득이 됐고, 슬래시 명령과 스킬로 반복 작업을 손에 맞게 묶는 법도 익혔다. 이 글 자체가 오늘 만든 `/study-upload` 자동화로 작성된 결과물이다.
